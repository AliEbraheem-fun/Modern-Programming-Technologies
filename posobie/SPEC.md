# Спецификация конверсии: сайт → учебное пособие

Документ для исполнителей. Описывает, как превратить `lectureN.md` + `practiceN.md` +
`quizN.md` в главу учебного пособия `chapters/chNN.tex`.

## 0. Что это за издание

**Учебное пособие** «Современные технологии программирования» (Java, Spring).
Финансовый университет при Правительстве РФ. Оформление по ГОСТ 7.60-2003.
Одна книга, 12 глав, целевой объём ~15 печатных листов (600 000 знаков).

Издание **самодостаточное**: читатель не имеет доступа к сайту, GitHub и интернету.
Всё, что нужно для понимания и выполнения заданий, должно быть в книге.

## 1. Структура главы (строго в этом порядке)

```latex
\chapter{Название главы}
\label{ch:NN}

<вводный абзац: чему научимся, зачем это нужно, связь с предыдущей главой>

\section{...}        % теория, 4–8 разделов
...

\praktikum{}         % практикум внутри главы
\subsection*{Задание 1. ...}
...

\kontrolvoprosy
\begin{enumerate} ... \end{enumerate}

\testzadaniya
\begin{enumerate} ... \end{enumerate}
```

Названия глав — по темам РПД (см. таблицу соответствия в разделе 8).

## 2. Объём — ЖЁСТКОЕ ТРЕБОВАНИЕ

Каждая глава имеет бюджет в знаках (см. `budget.json`). Отклонение вверх **не более
+15 %** (для главы 1: бюджет 31 498, предел 36 222). Это не пожелание: если каждая
глава превысит бюджет в полтора раза, книга выйдет 25 печатных листов вместо 15 и не
будет издана в таком виде. +15 % — это потолок, а не цель: тратьте запас только там,
где без материала глава перестаёт быть самодостаточной (см. раздел 10).

Считаются **все знаки файла**, включая исходники tikz-схем и листингов: в главе 1
это около 30 % объёма файла. Поэтому глава с большим числом диаграмм должна быть
скупее на прозу — отдельного «бюджета на схемы» нет.

**Перед сдачей посчитайте объём файла и сравните с бюджетом:**

```bash
python -c "import io;print(len(io.open('chapters/chNN.tex',encoding='utf-8').read()))"
```

Если превысили — сокращайте, пока не уложитесь. Сокращать нужно **примерно вдвое**
относительно исходников. Приоритет сокращения:

| Что режем | Насколько |
|---|---|
| Дублирующие примеры одного и того же понятия | оставить один лучший |
| Boilerplate в коде: импорты, геттеры/сеттеры, `toString()` | вырезать, заменить на `// ...` |
| Разделы «Попробуй в jshell!» | оставить максимум 1–2 на главу |
| Длинные справочные таблицы методов | оставить 5–7 ключевых строк |
| Практические задания | объединить похожие, оставить 3–5 заданий |
| Тестовые вопросы | из ~60 оставить 10–15 |

**Что НЕ режем:** объяснения «почему», бытовые аналогии, разбор частых ошибок,
связки между главами. Это ядро педагогической ценности.

**Чего резать нельзя вообще:** материал, на который опирается практикум вашей же
главы, если он не разобран ни в одной другой главе книги. Прежде чем выбросить
раздел исходника целиком, проверьте `grep`ом по остальным `lectureN.md`, подхватит
ли его кто-то ещё. Так, операторы (`/`, `%`, `&&`, `++`) не встречаются больше нигде,
и без них задания практикума главы 1 невыполнимы, — поэтому раздел «Операторы»
остался в главе, а место под него освободили сокращением раздела про JNI.

## 3. Правила текста

- Простой, но технический русский. Обращение к читателю на «вы».
- **Каждый листинг, рисунок и таблица предваряется абзацем прозы**, который
  объясняет, что читатель сейчас увидит и на что смотреть. Голых блоков быть не должно.
- Сохраняйте бытовые аналогии из исходника — это фирменная черта курса.
- Кавычки-ёлочки «…», длинное тире `~---`, неразрывный пробел `~` перед единицами.
- Термин при первом упоминании: `\term{внедрение зависимостей}` (\eng{Dependency Injection}).

## 4. Код

```latex
\begin{lstlisting}[language=Java,caption={Что делает этот код},label={lst:NN-x}]
public class Example {
    // ...
}
\end{lstlisting}
```

- Ширина строки кода — **не более 72 символов**, иначе вылезет за поля.
- Каждый листинг имеет `caption` и `label`.
- В тексте ссылка: `листинг~\ref{lst:NN-x}`.
- Комментарии в коде — на русском.
- Языки: `Java`, `XML`, `bash`, `SQL`, `HTML`, `C`. Для Kotlin — `kotlinlang`.
- Консольная сессия и вывод программы — листинг **без ключа `language`**
  (пример — сеанс `jshell` в главе 1): подсветка ключевых слов в выводе мешает.
- Листинги набираются стилем `gostcode` (он включён по умолчанию): рамка и номера
  строк уложены в полосу набора, а перед листингом преамбула требует минимум
  четыре свободные строки, чтобы он не начинался в самом низу страницы.

## 5. Рисунки

Диаграммы рисуются средствами LaTeX (`tikz` / `forest` / `pgfplots`),
**не картинками**. Исходные mermaid-блоки лежат в `posobie/mmd/chNN_figMM.mmd`.

Иерархия классов — через `forest` со стилем `hierarchy` (уже определён в преамбуле):

```latex
\begin{figure}[h]
\centering
\begin{forest} hierarchy
[Throwable
  [Error [OutOfMemoryError] [StackOverflowError]]
  [Exception [RuntimeException] [IOException]]
]
\end{forest}
\caption{Иерархия исключений Java}
\label{fig:NN-x}
\end{figure}
```

Линейные схемы — через `tikz` со стилем `box` (см. пример в `test_forest.tex`).

Правила:
- Подпись **под** рисунком, формат `Рис. 1.1 — Название` (даёт `\caption`).
- Ширина рисунка — **не более 16 см**. Широкие деревья разворачивайте вертикально
  (`grow'=0`) — так они компактнее.
- **Не размещайте два рисунка рядом по горизонтали.** Каждый рисунок — отдельным блоком
  на всю ширину. Иначе они уменьшаются и становятся нечитаемыми.
- На каждый рисунок должна быть ссылка в тексте: `рис.~\ref{fig:NN-x}`.

## 6. Таблицы

```latex
\begin{table}[h]
\caption{Модификаторы доступа}
\label{tab:NN-x}
\centering
\begin{tabular}{L{4cm}cccc}
\toprule
... \\
\midrule
... \\
\bottomrule
\end{tabular}
\end{table}
```

- Подпись **над** таблицей, формат `Таблица 1.1 — Название`.
- Ширина — не более 16 см. Для длинных таблиц — `longtable`.
- Колонки с текстом — через `L{ширина}`, иначе таблица вылезет за поля.
- На каждую таблицу ссылка в тексте: `табл.~\ref{tab:NN-x}`.

## 7. Что убрать полностью

| Элемент исходника | Что делать |
|---|---|
| Ссылки на GitHub (`**Ссылка на GitHub:** ...`) | удалить; код должен быть в тексте |
| `![alt](lecture1_images/...)` | перерисовать в TikZ |
| Ссылки на `exam.html`, `quiz*.md` | удалить |
| «как мы разбирали в Лекции 5» | заменить на `в главе~\ref{ch:05}` |
| «Практика 7», «Практическое занятие 7» | «практикум главы~\ref{ch:07}» |
| HTML (`<details>`, `<div>`, `<style>`) | переписать средствами LaTeX |
| Эмодзи | удалить |

Ссылка на другую главу даётся строго нумерованной: `в главе~\ref{ch:10}`, без
названий вроде «в главе о тестировании». При изолированной сборке
(`python checkchapter.py NN`) такая ссылка не разрешается, и в отчёте появляется
строка «битых ссылок: 1 -> ['ch:10']» — это ожидаемо и не считается ошибкой
(на `ИТОГ: ОК` не влияет). Межглавные ссылки проверяются на полной сборке книги
через `build.py`.

## 9. Тестовые задания

В конце главы — 10–15 вопросов из `quizN.md`, отобрать лучшие (те, что проверяют
понимание, а не запоминание) и по всем темам главы, включая практикум. Каждый вопрос
набирается макросом `\vopros` из преамбулы: стем и четыре варианта.

```latex
\testzadaniya
\begin{enumerate}

\vopros{Что произойдёт при сравнении строк через \texttt{==}?}
  {сравнение содержимого}
  {сравнение ссылок}
  {ошибка компиляции}
  {всегда \texttt{false}}

\end{enumerate}
```

Макрос сам расставляет метки а), б), в), г) и заворачивает варианты в `samepage`,
чтобы страница не разорвала вопрос между формулировкой и вариантами (в печати
читатель обязан видеть их одновременно). Набирать варианты обычным вложенным
`enumerate` **нельзя**: автоматических кириллических меток второй уровень списка в
этой сборке не даёт — `\setlist[enumerate,2]{label=\asbuk{enumii})}` печатает пустые
метки, а без настройки выходят латинские «(a) (b) (c) (d)», которые не совпадут с
ключами. Если вариантов не четыре, повторите приём макроса вручную: `\item`
снаружи, `\begin{samepage}\begin{enumerate}\item[а)] …\end{enumerate}\end{samepage}`
внутри.

Правильные ответы **в главу не попадают** — они собираются в приложение.
Вместе с главой сдайте файл `keys/chNN.json`:

```json
{"chapter": 4, "keys": [{"n": 1, "answer": "б"}, {"n": 2, "answer": "г"}]}
```

Порядок ключей — порядок вызовов `\vopros` в главе; в `answer` пишется кириллическая
буква варианта.

## 10. Самодостаточность — критерий приёмки

Читатель с книгой и компьютером без интернета должен суметь:
- понять теорию, не заглядывая никуда ещё;
- набрать код примеров с листа и запустить;
- выполнить задания практикума;
- проверить себя по контрольным вопросам и тестам.

Если задание требует зависимость, команду или файл — они должны быть приведены в тексте.
Проверьте на своей главе:

- каждое понятие, которое проверяет задание практикума, объяснено в теории этой же
  главы или в одной из предыдущих (со ссылкой `\ref{ch:NN}`);
- команды приведены целиком и в рабочем виде; для кода с кириллицей это
  `javac~-encoding UTF-8 Файл.java`, а для консоли Windows — `chcp 65001`;
- сказано, как запускать фрагменты кода из теории (они, как правило, представляют
  собой тело метода, а не готовый класс);
- у каждого класса стандартной библиотеки, который встречается в задании, названы
  пакет и возвращаемый тип, если от них зависит ответ.
